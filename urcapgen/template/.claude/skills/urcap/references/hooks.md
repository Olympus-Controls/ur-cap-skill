# Hooks: behaviour the spec can't express

Each node has two hook files, created once by `gen` and then yours:

| | PolyScope 5 | PolyScope X |
| --- | --- | --- |
| installation / program node | `ps5/src/<package>/<Node>Hooks.java` | `psx/<id>-frontend/<node_id>.hooks.js` |
| toolbar | `ToolbarHooks.java` | `toolbar.hooks.js` |

`<Node>` is the node id in CamelCase. The installation node's id is the URCap id with
underscores (`my-cap` → `my_cap`, `MyCapHooks.java`).

## The hooks

| hook | runs | must match on both platforms? |
| --- | --- | --- |
| `script(values, rendered)` → URScript | when the program is generated. `rendered` is the spec template already filled in | **yes**, line for line |
| `scriptAfter(values, rendered)` | after the children (only with `allows_children`) | **yes** |
| `validate(values)` → reason or null | whether the node is ready to run (PS5 green/yellow; PSX validator). After the spec's own min/max checks | **yes**: parity compares ready/not-ready |
| `extendUI(panel / el, …)` | under the generated form | no: each platform's own UI |
| toolbar `extendUI`, `opened`/`closed` (PS5), `closed` (PSX) | the popup / sidebar panel | no |

Values:

- **Java:** `Map<String, ScriptTemplate.Value>`. Read with `v.get("force").asDouble()`,
  `asInt()`, `asBool()`, `asString()` (a choice gives its value), `asPose()`, and
  `literal()` for the URScript literal.
- **JS:** a plain object, `{force: 50, wait: true, mode: "fast", target: [x, y, z, rx, ry, rz]}`.
  For a literal: `self.Urcapgen.literal("float", values.force)`.

## Keep the two in parity

`./urcapgen parity <id>` runs both `script` hooks (and `validate`) over dozens of value
cases: defaults, limits, every choice, flipped bools, awkward floats. It fails on any line
that differs. CI runs it on every change. Rules that keep it green:

1. **Format numbers with the runtime, not by hand.** Java's `Double.toString` and JS's
   `String(x)` disagree (`1.0E-4` vs `0.0001`). Use `ScriptTemplate.number(x)` and
   `Urcapgen.number(x)`, which are identical.
2. **Same logic, same order.** Write one, then port it line for line. Keep the hook short:
   anything complex belongs in a URScript `def` in the installation preamble, with the hook
   only calling it.
3. **No platform facts in the script.** Things like the PolyScope version, the robot
   model, or "is the daemon local" don't belong in the script. If you truly need them, put
   them in the installation preamble as a global, generated by the platform that knows them.
4. **Prefer the template.** Most "conditional script" needs are a `{{#key}}` or
   `{{#key=value}}` section in the spec, with no hook at all.

When a hook file is untouched, parity also checks both against the reference renderer. Once
you edit it, only the PS5↔PSX comparison remains. That comparison needs a JDK, or Docker as
the fallback. `--no-java` warns that it couldn't compare.

## Example: a computed line

Spec field `count` (int) and `pitch` (float, m). The script needs one `movel` per part,
which a template can't loop over:

```java
// PickRowHooks.java
static String script(Map<String, ScriptTemplate.Value> v, String rendered) {
    StringBuilder b = new StringBuilder(rendered);
    int n = v.get("count").asInt();
    for (int i = 0; i < n; i++) {
        b.append("movel(pose_trans(row_start, p[")
         .append(ScriptTemplate.number(i * v.get("pitch").asDouble()))
         .append(", 0, 0, 0, 0, 0]), a=0.5, v=0.1)\n");
    }
    return b.toString();
}
```

```js
// pick_row.hooks.js
script(values, rendered) {
  const U = self.Urcapgen;
  let out = rendered;
  for (let i = 0; i < values.count; i++) {
    out += `movel(pose_trans(row_start, p[${U.number(i * values.pitch)}, 0, 0, 0, 0, 0]), a=0.5, v=0.1)\n`;
  }
  return out;
},
```

(`i * pitch` is the same IEEE double in both languages; `number()` formats it identically.)

## Example: extra UI

PS5 (`extendUI(JPanel panel, ViewAPIProvider api)`): add Swing components to `panel`. For
input, use the pendant keyboard
(`api.getUserInterfaceAPI().getUserInteraction().getKeyboardInputFactory()`); a plain
`JTextField` gets no on-screen keyboard. PS5 can't change the node's values from here. Put
what must be saved in a spec field.

PSX (`extendUI(el, ctx)`): `ctx.node`, `ctx.api` (PolyScope's presenter API),
`ctx.values()`, and `await ctx.save()` after changing `ctx.node.parameters`. This runs in
the page, never in the worker.

## Extra files

A helper Java class: put it beside the hooks in the same package directory, without the
GENERATED header. It's compiled in.

A helper script on PSX: put it in `psx/<id>-frontend/` and load it from the hooks file. In
the worker use `importScripts("helper.js")`; in the page, the presenters load the hooks
file with a `<script>` tag, so the hooks file must load the helper the same way.
